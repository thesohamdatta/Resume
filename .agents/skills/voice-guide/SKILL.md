# Voice Guide

Language and tone only. The single voice authority is `docs/voice.md`; read it instead of
restating it here. Candidate facts come from the canonical evidence system (see `AGENTS.md`).

## Contexts

- `referral`: clear, broad, practical
- `startup`: direct, builder-oriented, ownership-heavy
- `mnc`: conventional, technical, ATS-readable

## Core rule

Write like a technically capable person describing work they actually did: specific nouns,
concrete verbs, short sentences, real technical details, real constraints, real decisions,
verified outcomes, natural rhythm.

## Ownership

Use the weakest verb that remains accurate.

used ≠ integrated ≠ implemented ≠ designed ≠ owned ≠ architected

For open source: issue ≠ implementation, proposal ≠ merge, approval ≠ merge,
downstream adoption ≠ authorship, draft ≠ shipped.

## Final human test

Read the resume once without knowing who wrote it. Ask: would a real engineer write this
sentence this way? If not, simplify it.

**Evidence over adjectives. Specificity over polish. Clarity over performance.**
