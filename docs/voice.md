# Voice Guide: Resume & Career Documents

## Purpose

Use this file for language and tone. Candidate facts come only from the canonical evidence system.

## Core voice

Write like a technically capable person describing work they actually did.

Principles:

- simple
- direct
- specific
- compact
- calm
- technically grounded
- human

The goal is not to sound impressive. The goal is to make real work easy to understand.

## Sentence test

For every line, ask:

1. Is it true?
2. Is it useful here?
3. Is it specific?
4. Could Soham explain it in an interview?
5. Would a human actually write it this way?

If the answer to the last question is no, simplify it.

## Prefer

Built  
Developed  
Implemented  
Designed  
Integrated  
Adapted  
Tested  
Evaluated  
Diagnosed  
Investigated  
Validated  
Authored  
Contributed

Use the verb that matches the evidence. Do not rotate verbs mechanically.

## Avoid

Do not use generic filler such as:

passionate  
innovative  
cutting-edge  
revolutionary  
visionary  
world-class  
transformative  
next-generation  
results-driven  
highly motivated  
proven track record  
dynamic professional  
leveraged  
utilized  
spearheaded  
orchestrated  
seamless  
robust  
scalable

These words are especially weak when they replace evidence.

## Anti-AI writing rules

Do not:

- make every bullet follow the same grammatical pattern
- force Action + Method + Result into every line
- stack three adjectives before every noun
- repeat the same verb because it "sounds professional"
- add claims of impact without an observable basis
- mirror the job description sentence-by-sentence
- over-explain ordinary work
- use polished language to hide uncertainty
- manufacture personality through slang

Natural variation is better than artificial variation.

## Density

Prefer:

**Fact → Action → technical detail → consequence/constraint**

Keep the shortest form that preserves meaning.

A distinctive technical detail is more useful than a generic adjective.

## Ownership

Use the minimum verb strength supported by evidence.

Examples:

used ≠ implemented  
implemented ≠ designed  
designed ≠ owned  
owned ≠ architected

Also preserve open-source status:

issue ≠ implementation  
proposal ≠ merge  
approval ≠ merge  
downstream adoption ≠ authorship  
draft ≠ shipped

## Startup mode

Startup resumes may show more ownership, decisions, product context, and technical range.

Still:

- no founder mythology
- no hype
- no fake confidence
- no quirky copy
- no inflated scale

Distinctiveness should come from the work itself.

## MNC mode

Keep language conventional and precise.

Use standard technical terminology naturally.

Do not keyword-stuff.

Do not write to an imaginary ATS score.

## Referral mode

Keep wording broad and easy to understand.

Technical credibility matters, but jargon should not dominate the page.

## Humanization pass

Before final output:

1. Read every bullet once as if reviewing someone else's resume.
2. Remove words that only make the sentence sound impressive.
3. Replace vague language with the concrete thing that happened.
4. Break repetitive sentence patterns.
5. Preserve unusual technical details when they are real and useful.
6. Check that each line still sounds like something Soham would say.

## Zinsser test

Can the sentence lose a word without losing meaning?

Can the adjective be replaced by evidence?

Can two sentences become one?

Can the same fact be said more plainly?

Do that.

## Final rule

**Evidence over adjectives. Specificity over polish. Clarity over performance.**

The resume should sound like Soham became more precise, not like a language model became more enthusiastic.
