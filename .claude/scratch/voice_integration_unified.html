🎯 Integration Approach

Direct voice.md Injection (Recommended)

Best for: Clean replacement, no skill dependencies, single source of truth

How it works:

  1. Stage 10 loads voice.md directly (full file)
  2. Applies context-specific rules from Voice Matrix (§5)
  3. Uses Banned Words table + Zinsser replacements inline
  4. Runs Pre-Send Checklist before output

Reads:
- versions/{track}/resume_{Company}.md (post-Stage 09)
- applications/{Company}_{date}/cover_letter.md (post-Stage 09)
- D:\download\resume\voice.md (FULL — single voice authority)
- pipeline_state.md ## Stage 05 (for target context detection)
- data/facts.yaml + content/github/evidence.md (drift anchors)

Produces: final overwrites in place + pipeline_state.md → Stage 10 log

VOICE CONTEXT (loaded from voice.md):
- Core Principles: Simplicity, Clutter, Be Yourself
- Banned Words: zero tolerance, auto-replace with Zinsser table
- Evidence Boundaries: hard constraints per project (never cross)
- Bullet Formula: Voice Matrix §5 (startup/MNC/mid-level from Stage 05)
- Pre-Send Checklist: items 1,2,3,9,11 (mandatory)

WORKFLOW:
1. LOAD: Read voice.md fully before touching drafts
2. DETECT CONTEXT: Read Stage 05 → target company type (startup/mnc/mid)
3. SELECT VOICE PROFILE: Voice Matrix §5 → bullet formula + tone
4. APPLY RULES (both resume + cover letter):
   - Banned Words scan → replace with voice.md Zinsser alternatives
   - Core Principles: strip to cleanest, cut 50%, builder identity
   - Evidence Boundaries: audit claims against facts.yaml/evidence.md
   - Bullet formula: apply context-specific pattern
5. RESUME PASS (strict hygiene):
   - Adverbs out, passive → active with human actor
   - No Wh- openers, no throat-clearing, no binary contrasts
   - Varied sentence length, no punchy one-liners
   - Zero em dashes (comma or period only)
   - Keep: standard headings, hyperlinks, technical specificity
6. COVER LETTER PASS (voice-preserving):
   - Minimum effective edit only
   - Keep writer's vocabulary, cadence, bluntness
   - Cap 300 words (trim most padded sentence per paragraph if over)
   - Banned-outright words (voice.md list) → delete unless quoted
7. DRIFT GATE:
   - Diff every edited line vs facts.yaml/evidence.md
   - Any new claim/number/strengthened verb with no anchor → FAIL
8. PRE-SEND CHECKLIST (voice.md items 1,2,3,9,11):
   - Company-specific, evidence-backed, honest scope, Zinsser test, context match

HARD RULE: never invent or alter facts. Numbers, metrics, claim strength
stay exactly as Stage 07/09 approved. Slop fix that changes meaning = FAIL.
