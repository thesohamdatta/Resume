## 4. Aura / Wearable AI

### 4.1 Product Concept
- **Repository**: [`thesohamdatta/aura`](https://github.com/thesohamdatta/aura) (1,562 files across hardware, firmware, backend, charts, and docs).
- **Core Premise**: *"Voice in. Memory out. No screen."* An ambient, screenless wearable pendant designed to record conversational context, compress and stream audio continuously, transcribe via self-hosted speech models, and construct an evolving personal memory graph.

### 4.2 Hardware & Embedded Implementation
- **Microcontroller Target**: Seeed Studio XIAO ESP32-S3 Sense (Xtensa dual-core LX7 @ 240MHz, 8MB PSRAM, 8MB Flash).
- **Audio Capture & DSP**:
  - [`firmware/src/mic.cpp`](https://github.com/thesohamdatta/aura/blob/main/firmware/src/mic.cpp) / `mic.h`: Configures I2S DMA circular buffers for continuous 16kHz 16-bit PCM audio acquisition.
  - [`firmware/src/opus_encoder.cpp`](https://github.com/thesohamdatta/aura/blob/main/firmware/src/opus_encoder.cpp) / `opus_encoder.h`: Implements on-device Opus compression to minimize network payload and transmission power consumption.
  - [`firmware/src/main.cpp`](https://github.com/thesohamdatta/aura/blob/main/firmware/src/main.cpp): FreeRTOS event loops managing Wi-Fi/BLE connection states, audio streaming sockets, battery voltage ADC sampling, and low-power sleep modes.
  - [`firmware/src/ota.cpp`](https://github.com/thesohamdatta/aura/blob/main/firmware/src/ota.cpp): Over-the-air firmware update handler.
  - Binary firmware releases: [`firmware/releases/aura_glass_firmware.uf2`](https://github.com/thesohamdatta/aura/blob/main/firmware/releases/aura_glass_firmware.uf2).
- **Physical Case**: Custom 3D CAD design file [`hardware/CASE.stl`](https://github.com/thesohamdatta/aura/blob/main/hardware/CASE.stl) specifically shaped for pendant form factors.

### 4.3 Cloud Backend & Memory Engine
- **Framework**: Asynchronous Python FastAPI backend (`backend/routers/`).
- **Core Router Modules**:
  - `backend/routers/transcribe.py`: Streaming audio ingestion endpoint handling chunked uploads.
  - `backend/routers/memories.py`: Context extraction, fact extraction, and memory segmentation.
  - `backend/routers/knowledge_graph.py`: Relationship linking between entities, people, dates, and topics.
  - `backend/routers/mcp.py` & `backend/routers/mcp_sse.py`: Model Context Protocol server exposing tool capabilities to external LLMs.
  - `backend/routers/speech_profile.py`: Speaker identification and voice profile enrollment.
- **Database & Storage Migrations**:
  - `backend/migrations/005_backfill_memory_vectors.py`: pgvector vector similarity index migrations for semantic context retrieval.
- **Production Kubernetes Infrastructure**:
  - Production Helm charts located in `backend/charts/backend-listen/` (Deployment, Horizontal Pod Autoscaler, Ingress, CronJobs).
  - Self-hosted ASR: Production Helm charts for deploying Deepgram Nova-2 / Nova-3 clusters (`backend/charts/deepgram-self-hosted/nova-3/Chart.yaml`).

### 5.1 `Mia` (Agent CLI & Execution Engine)
- **Repository**: [`thesohamdatta/Mia`](https://github.com/thesohamdatta/Mia)

  - `claude-adapter.ts`: Anthropic Claude Code / SDK integration.
  - `codex-adapter.ts`: OpenAI GPT / Codex provider adapter.
  - `hermes-adapter.ts`: Local model execution adapter.
  - `opencode-adapter.ts`: OpenCode runtime integration.
- **Skill Execution Engine** (`core/skills/`):
  - `grill/execute.ts`: Interactive Socratic questioning phase to extract constraints and eliminate ambiguities before coding.
  - `spec/execute.ts` & `plan/execute.ts`: Automated generation of technical specifications and test plans.
  - `review/execute.ts` & `ship/execute.ts`: Automated quality verification (lint, typecheck, test suites, git commit/PR creation).
  - `memory/execute.ts` & `learn/execute.ts`: Extracting project-level rules from failed sessions into permanent rulesets.
- **Persistence & Audit** (`core/state/`):
  - `jsonl-store.ts`, `store.ts`, `unified-store.ts`: Structured JSONL execution logging and rollback state tracking.
- **Architectural Decision Records**:
  - `docs/decisions/ADR-0001-eliminate-daemon.md`: Formal decision replacing a long-running background daemon with stateless event-driven CLI execution to prevent state drift and orphaned background processes.

## 14. Things We Should NOT Claim

To maintain absolute factual credibility when writing future engineering profiles, avoid the following claims:

1. **Do NOT claim mass manufacturing or commercial retail shipments for `aura`**:
   - *Fact*: The hardware is an open-source prototype built on Seeed Studio XIAO ESP32-S3 breakout boards and 3D printed STL cases, not a mass-manufactured custom ASIC/PCB in commercial distribution.
2. **Do NOT claim massive production user bases or cloud scale without metrics**:
   - *Fact*: The repositories contain infrastructure code (Helm charts, Dockerfiles, Kubernetes manifests), but there are no public telemetry logs proving active thousands of daily active users.
3. **Do NOT claim original authorship of forked repositories**:
   - *Fact*: Projects like `about`, `open-wearables`, `podcastfy`, `open-notebook`, `Sentient`, `SAMANTHA-OS1`, and `remma-o1` are forks. Only personal original code in `aura`, `Mia`, `LLM-Council`, `John`, `voicecoder`, and `codeshot` should be attributed as primary authorship.
4. **Do NOT claim that conceptual specs represent deployed operating systems**:
   - *Fact*: `OS-ONE` and `Aura-soul.md-` are theoretical Markdown/LaTeX design documents and identity specifications, not compiled kernel operating systems.
